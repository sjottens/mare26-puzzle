# maré26 — Decisions & assumptions

Living log. Every autonomous design/engineering decision goes here, newest milestone last.

## Milestone 1 — Setup

| # | Decision | Why |
|---|----------|-----|
| 1 | **Next.js 16 (App Router), React 19, TypeScript 5.9 strict**, Tailwind 4, ESLint 9, Vitest 5, Playwright. | Latest stable that the eslint/Next toolchain supports. TypeScript 7 (native) and ESLint 10 exist but `eslint-config-next` targets TS 5 / ESLint 9. |
| 2 | **`output: 'export'` with `trailingSlash: true`, `images.unoptimized`.** Single route (`/`); screens are client-side state, not URLs. | Required for later Capacitor wrapping (`webDir: out`). One HTML shell also makes offline trivial and avoids deep-link/404 issues on file:// or app webviews. |
| 3 | **Cookie names are ASCII: `mare26_v1_N`** instead of `maré26_v1_N`. | RFC 6265 cookie names are ASCII tokens; non-ASCII names are handled inconsistently across browsers/WebViews and can silently fail to save. The product name stays "maré26" everywhere users see it. |
| 4 | **Hand-rolled service worker** (`scripts/sw-template.js` + `scripts/build-sw.mjs`, run by `npm run build`) instead of Serwist. | Next 16 uses Turbopack by default and `@serwist/next` is a webpack plugin. The SW precaches every file in `out/` (hash-versioned cache), cache-first, with `/` as navigation fallback. ~50 lines, no dependency, fully offline. Verified by an e2e test that reloads while offline. |
| 5 | SW **does not `skipWaiting`**; a new version takes over on next launch. | Prevents an open session from mixing old HTML with new hashed chunks. |
| 6 | SW registers **only in production builds**. | Avoids HMR conflicts in dev. |
| 7 | **No web fonts**; rounded system font stack (`ui-rounded`, Nunito if present, system-ui). | `next/font/google` needs network at build time and adds requests; a system stack is instant, offline-safe and keeps Dutch diacritics crisp. |
| 8 | **Viewport does not disable zoom.** Pinch/scroll suppression is done per-element via `touch-action` on the game canvas (milestone 4). | Disabling page zoom globally is an accessibility failure. |
| 9 | **Layer boundaries enforced by ESLint**: `src/game` may not import React, Next, Three, or other `src` layers. | The spec requires a pure-TS core; a lint rule keeps it true as the code grows. |
| 10 | Path aliases `@/*` → `src/*`, `@content/*` → `content/*`. Puzzle data lives in `/content/puzzles`. | Matches requested structure. |
| 11 | PWA icons are **generated by script** (`npm run icons`, pure Node PNG encoder): a bevelled pink pixel-heart on indigo; the same art is used for `any` and `maskable` (it sits inside the safe zone). | No binary assets to hand-maintain; original art. |
| 12 | Tailwind 4 with CSS design tokens (`--bg`, `--ink`, `--brick`, …) in `globals.css`. Dark mode follows `prefers-color-scheme` unless `data-theme` is forced (settings later). | Pastel light default, readable dark variant; tokens make high-contrast mode a single override. |
| 13 | Global 44×44px minimum size for buttons/links/role=button in CSS. | Spec: 44px touch targets. |
| 14 | Node 22 / npm 11 assumed. `@types/node` pinned to 22 to match. | Matches the dev machine and Vitest 5's peer range. |
| 15 | `npm run serve` is a tiny dependency-free static server for `out/` on port 4173, used by Playwright and offline checks. | Avoids an extra dev dependency. |
| 16 | No git repository was initialised. | Not requested. |

## Milestone 2 — Core logic (src/game, pure TypeScript)

| # | Decision | Why |
|---|----------|-----|
| 17 | **Cell encoding is shared by player and solver:** 0 = empty/unknown, 1 = filled, 2 = crossed/known-empty. Grids are row-major `Uint8Array`s. | The player's board can be fed straight into the solver and hint engine with no conversion. |
| 18 | **Empty line clue is `[]`** internally; the UI displays "0". | Keeps run-length math uniform. |
| 19 | **Line solver is an exact prefix/suffix DP**, not the classic "leftmost/rightmost overlap" heuristic. It finds every cell that is the same in *all* valid arrangements of a line. | Strictly stronger than overlap logic, still O(n·k), and it was cross-checked against brute force on 3,000 random lines with random (even contradictory) knowledge. |
| 20 | **Difficulty** = 0.6·sizeTier + 0.8·passTier + guessing penalty, mapped to levels 1–5. A "pass" is one row sweep + one column sweep that changed something. Computed at runtime/validation, never stored in puzzle data. | Data stays a single source of truth; the formula can be retuned without editing 120 puzzles. |
| 21 | **Uniqueness = propagation + bounded backtracking** (200k node budget). "Unique" is only claimed when the search was exhaustive; an exhausted budget is reported as unproven. | Never certify a puzzle we could not prove. Verified against brute-force enumeration on random small grids. |
| 22 | **`validate:puzzles` also fails puzzles that need guessing** (line logic must finish them), in addition to non-unique and unrecognizable ones. | The hint engine promises "a logically deducible cell", and Challenge mode punishes wrong guesses, so guess-only puzzles would be unfair. |
| 23 | **Recognizability is a heuristic gate** (density 25–75%, largest part ≥ 60% of the picture, limited separate parts, uses ≥ 70% of the canvas). It catches junk; final judgement is a human look at the ASCII preview (`--preview`). | Automated checks cannot tell a tulip from a blob. |
| 24 | **A line counts as satisfied when its filled runs equal the clue** (crosses ignored). In Relax mode this can reveal "this line is right" even though the board has no mistake display. | Standard nonogram behaviour and required for the clue check mark. |
| 25 | **Mistake definition:** filling a cell that is empty in the solution, or crossing a cell that is filled. | Both are provably wrong moves; used by Challenge hearts, "check my board", and hints. |
| 26 | **Undo/redo unit = one drag stroke** (or one hint / auto-cross batch). History is capped at 2000 entries. | Undo feels natural on a drag-paint game. |
| 27 | **Drag rules:** first cell decides mode. Pressing a tool on a cell that already has that mark erases that mark for the whole drag; otherwise the drag paints onto cells in the same state as the first cell (it never overwrites other marks). The drag locks to the start row/column on the first move to another cell, and skipped cells are interpolated. | Matches the spec, prevents accidental overwriting of crosses, and survives fast pointer moves. |
| 28 | **Hints return language-neutral data** (kind, line, cells, numeric params); the UI turns them into nl/en sentences. A hint applies **all** its cells (e.g. the whole "middle 4"), so the sentence is always true of what is revealed. Priority: mistake → complete/empty line → full line → overlap → single-line deduction → solution reveal (only when line logic is stuck). | `src/game` cannot import i18n; and the spec example ("…so the middle 4 must be filled") reveals several cells. |
| 29 | **Endless generator:** left-right mirrored blobby noise (majority-smoothed for ≥ 10×10), must pass the recognizability gate and be solvable by pure propagation (which proves uniqueness). Deterministic per seed. | Fast (≈ 1–3 ms per puzzle even at 20×20) and always guess-free. |
| 30 | **Daily puzzle:** local date key → day number since 2026-01-01 → position in a seeded shuffle of the pool that is reshuffled every full cycle. | Same puzzle for everyone on a date, no repeats until the pool is exhausted, no server. |
| 31 | **Puzzle data:** JSON arrays per pack in `content/puzzles/<pack>.json`; rows are strings (`.` empty, `#` = palette[0], `1`–`9` = palette index). Multi-colour is representable (palette + per-cell colour index are parsed and kept) but `parsePuzzle` rejects it until the solver supports coloured clues. | Meets "architecture must allow multi-colour later" without half-building it. |
| 32 | Tutorial puzzles (Plus 3×3, Heart 5×5, Tulip 5×5) live in `content/puzzles/tutorial.json` and go through the same validation. | One pipeline for everything. |

## Milestone 3 — Storage (cookies)

| # | Decision | Why |
|---|----------|-----|
| 33 | **`StorageAdapter` is async and payload-based** (`read/write/clear` of one opaque string). Encoding, checksum, migrations and debounce live above it (`wire.ts`, `migrate.ts`, `manager.ts`). The cookie adapter does its work synchronously inside the call. | A Capacitor/IndexedDB adapter can be swapped in without touching anything else, and a write started in `pagehide` still lands. |
| 34 | **Wire format:** JSON → lz-string `compressToEncodedURIComponent` → 8-hex FNV-1a checksum prefix. The same string is the **export code** (`M26:` prefix). Cookies: `mare26_v1_<n>`, chunk 0 starts with `<total>.`; 2400 chars per cookie (well under 4 KB with attributes); soft warning at 8 KB, refuse at 16 KB with a graceful `too-large` result and the old data untouched. | Cookie-safe alphabet, self-verifying, and a missing chunk is detected. A realistic "everything solved" save is about 2 KB compressed. |
| 35 | **Attributes:** `Path=/; Max-Age=33696000 (390 d); SameSite=Lax`, `Secure` only on https. Every save rewrites every chunk (refreshing expiry) and removes stale chunks. After writing, the adapter reads back and reports `unavailable` if cookies are blocked. | Spec; also makes "cookies disabled" a visible, non-crashing condition (banner in the app). |
| 36 | **Loading never throws:** corrupt/partial/unknown data → `normalizeSave` (drops unknown fields, clamps numbers, fixes types) or defaults, and the UI tells the player once. A future schema version is read best-effort. Version 0 (pre-release prototype) migrates to 1. | Cookies get cleared/edited; the app must never crash on them. |
| 37 | **Board progress** is a 2-bits-per-cell bitset, base64url (20×20 = 134 chars), stored only for the current puzzle. | Spec: compact, bitset. |
| 38 | Cookie reads happen only in `hydrate()` after mount; until then the UI renders English/skeleton content. | No SSR/hydration mismatch. |

## Milestones 4–7 — Board, feel, reveal, meta

| # | Decision | Why |
|---|----------|-----|
| 39 | **One screen shell, hash routes.** Screens are Zustand state; every screen change `pushState`s its own `#screen` URL (browsers collapse pushState calls that reuse the same URL, which made "back" skip screens — found by an e2e test). Leaving a finished game/tutorial uses `replaceState`. Browser/Android back = previous screen. | Works with static export + Capacitor; back button behaves. |
| 40 | **Rendering:** cubes, engraved crosses, studs and diorama towers are four `InstancedMesh`es sharing one `RoundedBoxGeometry`; toon material with a 4-step gradient; one directional + one hemisphere light; a baked blob texture as contact shadow (no shadow maps). `frameloop="demand"`: frames are requested only while something animates (springs, wave, camera, confetti). **No post-processing is used at all**, so there is nothing to disable on weak devices; `PerformanceMonitor` lowers the DPR instead. | Spec performance budget: about a dozen draw calls for the play scene at any board size. |
| 41 | **Clue numbers are HTML**, in sticky strips (13–18 px depending on board size). Their positions are written directly into element transforms from the 3D camera projection every frame, so they stay glued to the grid while zooming/panning without React re-renders. Cell size is capped (66 px) and boards below 22 px/cell start zoomed in (pinch/pan, double-tap toggles fit). | Crisp text on phones; picking uses the same camera so it is exact. |
| 42 | **Input:** mouse (left = selected tool, right = cross, middle = erase), touch (drag paint, long-press = cross, a second finger cancels the stroke and starts pinch/pan, double-tap fit on ≥ 15 boards), keyboard (arrows, Space, X, Backspace, Z, Y, H, Escape). Playing is fully possible by keyboard alone; the e2e tests solve puzzles that way. | Spec + accessibility. |
| 43 | **Challenge rules:** a wrong fill is auto-corrected into a cross and a wrong cross into a fill; at most **one heart per stroke**; 3 hearts; stars: 3 = no mistakes within the time budget, 2 = no mistakes (slow) or one mistake within 2× budget, 1 = solved. Budget = 2.5 s × cells × (0.8 + 0.2 × difficulty). Hints are free every 90 s of play in both modes. | Fair and easy to explain; one sloppy drag can't end a run. |
| 44 | **Auto-cross only crosses around lines whose fills match the solution** (not merely satisfy the clue). | Otherwise a wrong fill that happens to satisfy a clue would cross out a correct cell (caught by a unit test). |
| 45 | **Reveal:** guide gaps close, empties sink away, filled cells rise into towers of 1–4 bricks (height from distance to the picture's edge) with studs, the camera swoops out then orbits (auto-rotating, drag to rotate), 110 confetti bricks, fanfare, result panel. Leaving plays a "slide onto the shelf" hand-off. Reduced motion skips the swoop, confetti and animation. | Spec's emotional peak. |
| 46 | **Shelves are orthographic and linear** (world → pixels is one scale), so accessible DOM buttons sit exactly over the 3D dioramas. Solved puzzles stand upright as coloured relief plaques; unsolved/locked ones are dark silhouettes. Pack select and Museum share the component. | 44 px targets, keyboard/screen-reader access, no per-frame sync. |
| 47 | **Tutorial** = the 3 tutorial puzzles with a coach banner driven by board state; puzzles 1 and 2 auto-advance, 3 ends in the full reveal; a hint is available immediately there. Tutorial puzzles are **not** collectibles (not counted in stats or the Museum). | Under 60 s to finish; no confusing counts. |
| 48 | **Daily:** curated pool = every 10×10 and 15×15 puzzle (66 ids in `daily-pool.json`), date-seeded shuffle per cycle. **Streak** has one grace day (earned back every 7 days). **Endless:** seeds 1, 2, 3…, an unfinished one per size/mode is resumed. | Same puzzle for everyone; forgiving streak. |
| 49 | **Premium is a data-layer flag only:** `isPremium` = shelf order ≥ 30 (first 30 free = all of Dutch Icons + first 10 Animals); the start sheet shows a "coming soon" note. No payments. | Spec. |
| 50 | **Share:** Wordle-style emoji text + a 1080×1080 PNG composed from a snapshot of the 3D canvas; `navigator.share` (with the file when supported), else clipboard + download. | Spec. |
| 51 | **Audio:** everything is synthesized with WebAudio (click/cross/erase/hint/mistake/fail, a pentatonic line chime that climbs with combos, fanfare, and an optional soft lo-fi loop: chord pads, bass, hats, sparse melody). Created lazily on the first gesture; mute toggles and haptics (`navigator.vibrate`) in Settings. | No audio files; obeys the autoplay policy. |
| 52 | **Colourblind mode** adds studs to filled cubes; **high contrast** swaps to a black/white/yellow palette and CSS tokens; state is never colour-only (pressed height, engraved X, check marks). Dark/light follow the system unless forced. | Spec. |

## Milestone 8 — Content

| # | Decision | Why |
|---|----------|-----|
| 53 | **120 puzzles = 6 packs × 20**, each ordered by size: eight 5×5, eight 10×10, three 15×15, one 20×20. All art is original. Pictures are drawn with a tiny shape library (`art/lib.mjs`, `art/<pack>.mjs` → `node art/build.mjs <pack>`) or by hand. | Gentle difficulty ramp inside every pack. |
| 54 | **`npm run repair:puzzles`** flips the fewest pixels in the *ambiguous region* so a picture becomes unique and guess-free; **`npm run sheet:puzzles -- <pack>`** renders a contact-sheet PNG for reviewing a whole pack at a glance. The validator also enforces 20 puzzles per pack, 3 tutorial puzzles and a valid daily pool. | Hand-drawn pixel art rarely satisfies the "solvable by logic" rule first time. |
| 55 | Some 5×5 pictures are deliberately simple and a few larger ones are stylised silhouettes; the committed JSON (after repair) is the source of truth. Recognizability was checked by the automatic gate plus a human look at contact sheets; the weakest pictures (e.g. the 5×5 planet, the comet, a few mid-size animals) are the first candidates for artistic polish. | Honest limits of a 5–20 pixel canvas. |

## Milestone 9 — Polish, accessibility, performance, tests

| # | Decision | Why |
|---|----------|-----|
| 56 | **Tests:** unit tests (logic with brute-force cross-checks, storage, game store, catalog, i18n incl. placeholder parity) + Playwright: PWA offline reload, the full first-run flow with progress persisting across a reload, mouse drag painting on the 3D board, back navigation, and an axe WCAG A/AA scan of the main screens. Playwright runs Chromium with software WebGL, one worker. | Definition of done. |
| 57 | **The service worker precaches every exported file** (including the lazily loaded 3D chunks), so the whole game works offline after the first visit. | Spec. |
| 58 | **Known limits:** no real-device performance numbers were possible (only software WebGL in headless Chromium); Safari/iOS and a real Android phone were not tested; the 3D canvas itself is not covered by axe (it is `aria-hidden`, with the keyboard-driven DOM controls and live region as the accessible path). | Transparency. |
